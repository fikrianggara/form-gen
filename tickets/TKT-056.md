## Description

An organization admin can manage the accounts in their organization: list
members, change a member's role between org-operator and org-dev, remove
members, and toggle active state. Depends on the membership model from
TKT-055 (org-scoped roles live on `OrganizationMember`, not on `User.role`).

Owner request (2026-08-21): "bisa manajemen akun yang ada di organisasinya;
bisa ngubah role user jadi operator atau dev organisasi."

## Acceptance criteria

- [ ] Org page (admin view) lists all org members with their org role,
      join date, and status.
- [ ] Org admin can change a member's org role: org-operator ↔ org-dev
      (the set of roles an org admin may assign is scoped — they cannot grant
      global ADMIN or global DEV, which remain system-level).
- [ ] Org admin can remove a member; removal clears their active-membership
      shortcut (User.organizationId) and revokes org-scoped key visibility
      (TKT-057).
- [ ] Org admin cannot remove/demote themselves as the last org admin
      (mirror the LAST_ACTIVE_ADMIN guard from TKT-029).
- [ ] System ADMIN sees all orgs and can assign any org role, including org
      admin.
- [ ] UI uses labeled action menus (kebab popup, per the Fikri UX
      preference) — no hidden clickable badges.
- [ ] Integration tests: role change grants/revokes ISSUE_API_KEYS-equivalent
      org permission, last-org-admin guard, removal revokes access.

## Notes

- The org-dev role grants org-scoped key visibility via TKT-057; the role
  change here is the management surface for it.
- Do NOT conflate org roles with the global `Role` enum — they are distinct
  concepts after TKT-055.
