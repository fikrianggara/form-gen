## Description

The `/api/v1/*` read-only surface (analysis v03 §4, owner decision: read-only
v1). Bearer-key auth, scope enforcement per route, page/pageSize pagination,
stable envelope. POST response submission is explicitly deferred to v2.

## Acceptance criteria

- [x] `GET /api/v1/health` — public, no auth; returns `{ data: { status, version } }`
- [x] `GET /api/v1/questionnaires` — questionnaires:read; page/pageSize meta; optional status filter
- [x] `GET /api/v1/questionnaires/{id}` — questionnaires:read; detail incl. blocks/questions/options; 404 envelope when missing
- [x] `GET /api/v1/questionnaires/{id}/responses` — responses:read; paged; filters status/from/to
- [x] `GET /api/v1/responses/{id}` — responses:read; response detail with answers; 404 envelope when missing
- [x] `GET /api/v1/questionnaires/{id}/report` — reports:read; aggregated KPIs + per-question stats
- [x] `GET /api/v1/masters` — masters:read; paged master data
- [x] `GET /api/v1/option-sets/{id}` — option-sets:read; option set detail incl. options
- [x] All authenticated routes use the `withApiKey` wrapper (auth → scope → rate-limit → log); no `POST` routes exist in v1
- [x] Response shapes follow the standard envelope: `{ data }`, `{ data, meta }` for lists, `{ error: { code, message } }` for failures
- [x] Integration tests exercise auth (401), scope (403), pagination, and each endpoint against the per-ticket test DB
