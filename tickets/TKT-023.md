## Description

Public response endpoints (`POST /api/questionnaires/[slug]/responses`,
`PATCH .../responses/[id]`) are unthrottled — anonymous bots can spam Response
rows and payloads (storage/CPU DoS) on any ACTIVE questionnaire. The
`rate-limit.service.ts` exists but is wired only to the dashboard login.
From finding F-004.

## Acceptance criteria

- [ ] Rate limiting on POST/PATCH response routes per (respondentToken/IP)
- [ ] Configurable window/limit; documented constants
- [ ] 429 with stable error shape when the limit is hit
- [ ] Rate-limit service generalized/reused beyond login (rename if needed);
      existing login rate-limit tests stay green
- [ ] Tests cover under/over limit and window expiry
