## Description

The responses list page only offers a "View" link per respondent. Admins and
operators who own the questionnaire need a per-respondent action menu to
view, edit, delete, and mailblast a response without leaving the page. The
same actions should be gated by questionnaire ownership.

## Acceptance criteria

- [ ] Questionnaire records its creator (createdBy); ADMIN can manage any questionnaire's responses, OPERATOR only their own (legacy unowned questionnaires stay manageable by any admin/operator)
- [ ] Responses list shows a per-row action button that opens a popup menu with View / Edit / Delete / Mailblast
- [ ] View opens the existing response detail page
- [ ] Edit opens the response prefilled and saves updates to answers (reusing the save engine)
- [ ] Delete removes the response (and its answers) after confirmation
- [ ] Mailblast sends the questionnaire's unique link to the respondent's email (reusing invitation + mail services); no response rows created by the blast itself
- [ ] Actions are permission-gated server-side (not just hidden in UI)
- [ ] Unit + integration tests green
