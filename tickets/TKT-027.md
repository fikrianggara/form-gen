## Description

Creating a user in the admin Users panel throws
`TypeError: Cannot read properties of null (reading 'reset')` on the success
path. `UsersPanel.tsx` called `e.currentTarget.reset()` inside the async
`run()` callback — React nulls `e.currentTarget` once the submit handler
returns, so the reset crashed. Role-agnostic (any successful create hits it).

## Acceptance criteria

- [x] Add-user form resets after a successful create without throwing — the
      form element is captured (`const form = e.currentTarget`) BEFORE the
      async server-action call, and `form.reset()` is called on success.
- [x] Failed creates (server error) still skip the reset and surface the error
      (behavior unchanged).
- [x] No other `currentTarget.*` usage remains after an async gap in `src/`
      (sweep clean).
- [x] Typecheck, lint, and the user.service integration suite pass
      (14/14 green).

## Notes

Root cause: React clears `event.currentTarget` after the event handler
dispatches; the awaited server action resolved later, so the reference was
null. Fix verified by code inspection + full gate (tsc, lint, tests).
