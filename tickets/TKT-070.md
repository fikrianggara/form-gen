## Description

Admin surface for the AI credit system (TKT-069): set the **global daily
default**, set a **per-user daily allowance** override, and **adjust a user's
credit balance** (top-up/revoke for the day) with an audit trail.

Owner request (2026-08-21): "Admin bisa set kredit harian default, set per
user, set kredit user."
Owner decision (2026-08-21, analysis v09): "set kredit user" = BOTH a
per-user allowance override AND a dated balance adjustment.

## Acceptance criteria

- [ ] New admin-only permission `MANAGE_AI_CREDITS` in `rbac.ts` (ADMIN
      only), required by every credit-management action.
- [ ] Admin page (new route under the admin section, reachable from the
      TKT-058 sidebar) shows: current global daily default (editable) + user
      table with each user's allowance (default/override), today's usage,
      and today's balance.
- [ ] Set global default: writes `AiCreditConfig.dailyDefault`; applies to
      users without an override immediately (next deduction uses it).
- [ ] Per-user allowance: set `User.aiCreditsPerDay` (nullable — clear to
      fall back to the default) via a labeled kebab action, per the
      explicit-action-menu convention.
- [ ] Balance adjustment: add a dated `AiCreditAdjustment` (delta ±N, reason
      required, createdBy recorded) — top-up or revoke for TODAY only;
      adjustments listed per user with reason + admin + timestamp.
- [ ] UI reflects immediately after save (R1 convention, analysis v06).
- [ ] Integration tests: default change applies to non-override users;
      override beats default; adjustment changes today's balance; audit rows
      recorded; non-admin action rejected.

## Notes

- Depends on TKT-069 (schema + service). Same group `ai-credits` → one
  branch, one merge.
- The adjustment is dated, so a "revoke" only affects the current day; the
  allowance override is persistent until cleared.
