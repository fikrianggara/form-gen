## Description

Public-facing portal where external parties request API access: they submit a
key request (name, email, organization, purpose, requested scopes) and an
admin approves or denies it (analysis v03 §9.1 owner decision). Approval
creates the ApiKey; requester receives the secret once.

## Acceptance criteria

- [x] Public request page (no login): requesterName, requesterEmail, organization?, purpose, requestedScopes; validation per lib/schemas conventions
- [x] Submit creates `ApiKeyRequest` with status PENDING; duplicate/abuse guarded by existing rate-limit service (per-IP)
- [x] Admin approval queue page (dashboard, ADMIN role only): lists PENDING requests with requester info + requested scopes
- [x] Approve → creates ACTIVE ApiKey with requested scopes, links `approvedKeyId`, shows secret exactly once (copy-to-clipboard), marks request APPROVED with reviewedBy/reviewedAt
- [x] Deny → marks request DENIED with reviewer metadata; no key created
- [x] Request status transitions enforced (PENDING → APPROVED|DENIED only); re-submission allowed for DENIED
- [x] Unit + integration tests: submit, validation, approve creates key + secret-once, deny, RBAC (non-admin forbidden)
