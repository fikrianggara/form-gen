## Description

Today `Questionnaire.surveyId` is a single FK — one questionnaire belongs to
ONE survey. The owner requires one questionnaire usable by MULTIPLE surveys.
Change the relation to many-to-many via a join table, backfill existing
data, and update every org-gate that assumed single-survey (analysis v05
§3.1–§3.3).

## Acceptance criteria

- [ ] `SurveyQuestionnaire` join model: surveyId + questionnaireId composite PK, both FKs onDelete Cascade, index on questionnaireId
- [ ] `Questionnaire.surveyId` column DROPPED; `Survey.questionnaires` and `Questionnaire.surveys` are implicit M2M relations
- [ ] Migration backfills existing `questionnaire.surveyId` rows into join rows before dropping the column; no data loss (verify count)
- [ ] Migration applied via `migrate diff` + `migrate deploy` (non-interactive); `npx prisma generate` succeeds
- [ ] `assertCanManageQuestionnaire` org gate updated: ADMIN any; OPERATOR manages when createdBy=them, legacy-null, OR **any** of the questionnaire's surveys belongs to their org
- [ ] `assignQuestionnaireToSurvey` → `connectQuestionnaireToSurveys(questionnaireId, surveyIds[])` (replace set); operators restricted to own-org surveys (reuse `assertCanAccessSurvey`)
- [ ] `listSurveys` questionnaire counts use the join (verify Prisma shape); OrgsPanel counts correct
- [ ] `npx tsc --noEmit` passes; unit tests for backfill + org-gate ANY-of-surveys semantics
