## Description

Today `Questionnaire.surveyId` is a single FK — one questionnaire belongs to
ONE survey. The owner requires one questionnaire usable by MULTIPLE surveys.
Change the relation to many-to-many via a join table, backfill existing
data, and update every org-gate that assumed single-survey (analysis v05
§3.1–§3.3).

## Acceptance criteria

- [x] `SurveyQuestionnaire` join model: surveyId + questionnaireId composite PK, both FKs onDelete Cascade, index on questionnaireId
- [x] `Questionnaire.surveyId` column DROPPED; `Survey.questionnaires` and `Questionnaire.surveys` are M2M relations (via the join)
- [x] Migration backfills existing `questionnaire.surveyId` rows into join rows before dropping the column; no data loss (dev form_gen: 0 linked → 0 join rows; count verified)
- [x] Migration applied via `migrate deploy` (non-interactive); `npx prisma generate` succeeds
- [x] `assertCanManageQuestionnaire` org gate updated: ADMIN any; OPERATOR manages when createdBy=them, legacy-null, OR **any** of the questionnaire's surveys belongs to their org (integration test added)
- [x] `assignQuestionnaireToSurvey` → `connectQuestionnaireToSurveys(questionnaireId, surveyIds[])` (replace-set, transaction, validates surveys exist); operators restricted to own-org surveys via `assertCanAccessSurvey` per survey
- [x] `listSurveys` questionnaire counts use the join (Prisma `_count` over the join relation); `listQuestionnaireSurveys` added for tags/editor
- [x] `npx tsc --noEmit` passes; org-gate ANY-of-surveys + replace-set + not-found + list tests green; full suite green (evidence: npm run test full pass)
