## Description

"Bikin proposal untuk membuat survei": a proposal step before a survey exists.
Draft a survey proposal (title, purpose, target, questions outline). Optional
verification step: send verification to an email address; the proposal moves
forward only when verification is approved. After approval, continue to the
"build questionnaire" step (wizard-style handoff).

## Acceptance criteria

- [x] Proposal model (draft → pending verification → verified → approved) —
      `Proposal` (organizationId, createdBy, title, purpose, target, outline,
      status, verifyEmail, verificationToken, verifiedAt, approvedAt, surveyId)
      with `ProposalStatus` enum; transitions enforced in the service.
- [x] Optional email verification step (configurable per proposal) —
      `submitProposal` with a `verifyEmail` moves to PENDING_VERIFICATION and
      mails a one-time token link (buildProposalVerificationMail via the
      TKT-013 mailer); without one it skips straight to VERIFIED.
      `/proposals/verify/[token]` confirms the token server-side.
- [x] Approve action that unlocks the questionnaire builder step —
      `approveProposal` creates the Survey (name = proposal title, same org),
      links `proposal.surveyId`, and the UI hands off to
      `/dashboard/new?surveyId=…&title=…` where the new questionnaire is
      created pre-attached to the survey.
- [x] UI: proposal list/form + step handoff into questionnaire creation —
      `/dashboard/proposals` (org-scoped, status badges, nav link),
      `/dashboard/proposals/new` (title/purpose/target/outline/verifyEmail,
      org picker for admins), `/dashboard/proposals/[id]` (detail + submit /
      approve actions), and the builder handoff.
- [x] Integration with survey/questionnaire creation (align with org scoping
      TKT-014) — proposals live in an organization; creation/listing/actions
      are org-scoped (operators own org, admins all); approval creates the
      Survey inside the proposal's org; questionnaire creation can attach to
      that survey via `createQuestionnaireAction.surveyId`.
- [x] Unit + integration tests green — 10 new proposal-service integration
      tests (create/validate, submit with/without email + mail capture,
      token verify + bad token, approve → survey creation, cannot approve
      DRAFT, org-scoped list, update); full suite 416/416 green; tsc + lint
      clean.

## Notes

Depends on TKT-014 (org scoping) — proposals create surveys inside an
organization. Email delivery reuses the mailer introduced by TKT-013.
Outline rows are captured as `{ title, type }` metadata (not auto-converted
into questions; the builder handoff continues from the proposal outline).
