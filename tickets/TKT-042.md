## Description

The org feature has no survey page: a survey shows "0 questionnaires" but
there is no way to connect existing questionnaires to it from the survey
side. Add a dedicated survey page (view details, connect/disconnect existing
questionnaires) and delete-survey in both the org page and the survey page
(analysis v05 §1, §2, §3.4).

## Acceptance criteria

- [x] Survey page route `/admin/surveys/[id]`: name, description, org, connected questionnaires list (server page + SurveyPanel client component)
- [x] Connect questionnaires: checkbox multi-select of EXISTING questionnaires (ADMIN all via listConnectableQuestionnaires; OPERATOR own + legacy + same-org per the manage rule); Save persists via `setSurveyQuestionnaires` (survey-side replace-set, validates ids)
- [x] Disconnect questionnaires: removes the join row only — the questionnaire is NOT deleted; inline Disconnect button per row
- [x] Delete survey on the survey page: inline confirm; deletes survey + join rows (FK cascade), KEEPS questionnaires; org gate ADMIN any / OPERATOR own org (assertCanAccessSurvey)
- [x] Delete survey in org page (OrgsPanel survey row): same semantics — survey rows now link to the survey page ("Manage") where delete lives
- [x] After delete/disconnect/connect, counts and lists refresh (revalidatePath /admin/surveys/[id] + /admin/orgs); errors shown via the shared toast/error pattern
- [x] Tests: survey-side replace-set, disconnect keeps questionnaire, delete keeps questionnaires + nulls Proposal.surveyId, picker scoping (ADMIN all / OPERATOR own+legacy+same-org only); full suite 473/473 green; tsc + lint clean
