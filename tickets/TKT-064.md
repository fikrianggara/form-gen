## Description

Improve the rule-builder UX for conditional question display. The engine
already exists (per-question `visibilityRule` TKT-006, block `entryRule`
TKT-007, `RuleSetsEditor`), but the owner found the generation/editor form
UX wanting: the user wants to **pick which question the current question
depends on and which value triggers display**, with **multiple rules**
(AND/OR) per question — through a friendly, explicit form.

Owner request (2026-08-21): "pertanyaan bisa ditampilkan opsional berdasarkan
rule, misal hanya ditampilkan kalau pertanyaan x nilainya y."
Owner decision (2026-08-21, analysis v08 Q6): not verify-only — fix the UX in
the questionnaire generation/editor form: user chooses the dependency
question + value; multiple rules supported to show a question.

## Acceptance criteria

- [ ] Rule builder UX in the questionnaire editor (and the AI generation
      form): for a question, "Show only if…" opens a form where the user
      picks the **dependency question** (from the questionnaire's own
      questions) and the **value/condition** (operator + option or free
      value) — no raw JSON editing.
- [ ] **Multiple rules** supported per question, combinable with AND/OR
      (the existing engine's rule-set model), each rule a row the user can
      add/remove.
- [ ] Persists into `QuestionnaireQuestion.visibilityRule` using the existing
      rule-set shape so the respondent engine (TKT-006/007) evaluates it
      unchanged; block entry rules still editable in the same surface.
- [ ] Verify end-to-end in the respondent UI: author a rule, confirm
      hide/show on change, including multi-rule AND/OR and edge cases
      (removed dependency question, empty prior answer, JSON values).
- [ ] UI reflects immediately after save (R1 convention, analysis v06);
      labeled controls — no hidden affordances.
- [ ] Component test for the rule builder (add/remove rules, save shape);
      integration test for respondent evaluation of a multi-rule set.

## Notes

- Engine exists — do not re-implement evaluation. The work is the authoring
  surface (pick dependency + value, multi-rule rows) + the verification.
  Evidence: TKT-006/007 (merged), `RuleSetsEditor.tsx`, `visibilityRule`
  `prisma/schema.prisma:384`, `entryRule` :368.
- Reuse `RuleSetsEditor`'s model where it already covers the shape; the gap
  is the "choose which question + which value" affordance.
