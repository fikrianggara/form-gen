## Description

The users table's Status badge is a hidden control: it renders as a flat
green/red pill but is actually a clickable button that toggles `isActive`.
There is no affordance — no hover state, no cursor, no tooltip — so admins
don't realize it toggles the account. Owner decision (2026-08-15): replace the
row's scattered inline actions with a **kebab action menu**, same pattern as
the responses table (TKT-017 `ResponseActionsMenu`), and make the Status
column a pure display badge. Enable/Disable is an explicit labeled action
(option b), not a hidden clickable badge.

## Acceptance criteria

- [ ] Status column shows a pure display badge (active green / disabled red),
      NOT a clickable control
- [ ] Actions column has a kebab button (IconMore) opening a popup menu with:
      Edit, Reset password, Enable/Disable
- [ ] Enable/Disable shows an inline confirm state in the menu (like the
      Delete confirm in ResponseActionsMenu) before toggling
- [ ] Menu closes on outside click and Escape; matches ResponseActionsMenu
      behavior
- [ ] Edit and Reset password keep today's inline row-expansion forms
      (triggered from the menu, not separate buttons)
- [ ] Permission gate unchanged (MANAGE_USERS, ADMIN only)
- [ ] No behavioral change server-side; tests green

## Notes

Owner decision 2026-08-15: use the popup action-menu pattern (like the
responses page) with option (b) — explicit Enable/Disable, not a clickable
badge. The Status badge being a hidden toggle was discovered by the owner in

Reuses the established ResponseActionsMenu interaction; consider extracting a
