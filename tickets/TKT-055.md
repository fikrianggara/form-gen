## Description

Replace the single `User.organizationId` membership
(`prisma/schema.prisma:170`) with a real membership model: an org admin
invites users by email, users can request to join an organization from their
profile, and the org admin approves or rejects both. This is the foundation
for org-scoped roles (TKT-056) and org-scoped key visibility (TKT-057).

Owner request (2026-08-21): "admin organisasi bisa invite user ke organisasi;
approve yang mau masuk ke organisasinya (user edit organisasi di profil)."
Owner decisions (2026-08-21, analysis v08): org admin = **role value on
OrganizationMember** (ADMIN within the org); **keep `User.organizationId`**
as the active-membership shortcut, synced on approve/leave.

## Acceptance criteria

- [ ] Schema: `OrganizationMember` model (id, userId, organizationId,
      role `ADMIN|OPERATOR|DEV` scoped to the org, status `PENDING|ACTIVE`,
      invitedBy, joinedAt, createdAt/updatedAt; unique [userId,
      organizationId]) — migration with backfill of existing
      `User.organizationId` rows as ACTIVE members.
- [ ] Org admin = `OrganizationMember.role = ADMIN`; the org creator becomes
      org admin on org creation; global ADMIN can also grant it.
- [ ] Org admin can invite by email: creates a PENDING membership + invite
      email with a token link (reuse `invitation.service` / `mail.service`
      patterns from TKT-019/020).
- [ ] Invited user accepts via the emailed link; existing user with no org is
      added directly; if the email has no account, the invite links to
      registration (TKT-051) and completes after signup.
- [ ] User can set/request an organization in their profile (see TKT-067):
      selecting an org creates a PENDING join request the org admin approves
      or rejects; leaving an org removes/archives membership.
- [ ] Org admin approval/rejection UI on the org page, with the R1 convention
      (UI reflects immediately, no reload required).
- [ ] Access-control helpers: `assertOrgAdmin(session, orgId)` and
      `assertOrgMember(session, orgId)` used by org-management actions.
- [ ] `User.organizationId` stays as the active-membership shortcut and is
      kept in sync on approve/leave (owner decision Q4); existing org gates
      (`assertCanAccessSurvey`, `assertCanManageQuestionnaire`) keep working
      unchanged.
- [ ] Integration tests: invite → accept, join request → approve/reject,
      leave, duplicate-membership rejection.

## Notes

- Big because it is the org layer's foundation: schema + migration + email +
  two approval flows + access-control helpers. TKT-056 and TKT-057 build on
  the membership model; do not start them before this merges.
- The org-invite email must use the absolute-base-URL pattern from TKT-019
  and HTML escaping from TKT-021.
