## Description

Modernize the UI with a design-token system (CSS variables for color, radius,
border, spacing) and add dark mode with a theme toggle. Today styling is
hardcoded Tailwind utility values (`bg-gray-50`, `text-gray-900`,
`border-gray-200`, indigo accents) across layouts and components; the root
layout is light-only (`src/app/layout.tsx:20`).

Owner request (2026-08-21): "refaktor UI dengan UI skill yang baru, tambah
dark mode."

## Acceptance criteria

- [ ] Token layer in `globals.css`: semantic CSS variables (background,
      foreground, muted, border, card, accent, danger, success…) wired to
      `dark` class / `prefers-color-scheme`; utility classes or Tailwind
      config mapping to tokens.
- [ ] Theme provider with manual toggle (light/dark/system) persisted in
      localStorage and applied before first paint (no flash of wrong theme).
- [ ] Toggle lives in the app-shell top bar (TKT-058) and respects the
      sidebar work — sequence so both touch the same layout once.
- [ ] All main surfaces themed: login, dashboard, editor, admin panels,
      landing page (landing may keep its brand look but must not break in
      dark mode).
- [ ] Contrast check: dark-mode text passes WCAG AA on card/background tokens
      (verify with contrast math — this profile has no image vision).
- [ ] No regression in tests; gate chain passes.

## Notes

- Sequence after or in the same wave as TKT-058 (nav shell) to avoid editing
  the layouts twice.
- The available `frontend-design-pro` skill is the reference for the design
  system; keep the change scoped to tokens + dark mode, not a full
  redesign, unless the owner extends scope.
