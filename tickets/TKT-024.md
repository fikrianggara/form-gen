## Description

Owner decision (2026-08-15, findings F-005 + F-008): replace the rigid
immutable-completed model with a **response status workflow**. Statuses:
`draft`, `submitted by respondent`, `edited by admin/operator`,
`approved by admin/operator`. Status changes are **stored in the database**,
creating an audit trail of who did what and when.

This resolves two gaps: (1) admin cannot edit COMPLETED responses
(`saveResponse` throws `RESPONSE_COMPLETED` — TKT-017's edit action fails
server-side with 409 for completed rows); (2) no provenance on admin edits.

## Acceptance criteria

- [ ] Response status model extended to the workflow statuses; completed →
      "submitted by respondent" semantics preserved for existing rows
- [ ] Status changes persist to the DB with actor (admin/operator user or
      respondent) and timestamp — an audit/history record per response
- [ ] Admin/operator can edit a submitted response; edit records the actor and
      moves status to "edited by admin/operator"
- [ ] Admin/operator can approve a response; approval is recorded
- [ ] Permissions: same gates as TKT-017 (MANAGE_QUESTIONNAIRES + ownership)
- [ ] Public respondent flow unchanged: respondents submit drafts/completions;
      only admins/operators move the workflow statuses
- [ ] Migration path for existing COMPLETED responses
- [ ] Unit + integration tests green (workflow transitions, audit records,
      permission gates)
