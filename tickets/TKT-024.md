## Description

Owner decision (2026-08-15, findings F-005 + F-008): replace the rigid
immutable-completed model with a **response status workflow**. Statuses:
`draft`, `submitted by respondent`, `edited by admin/operator`,
`approved by admin/operator`. Status changes are **stored in the database**,
creating an audit trail of who did what and when.

This resolves two gaps: (1) admin cannot edit COMPLETED responses
(`saveResponse` throws `RESPONSE_COMPLETED` — TKT-017's edit action fails
server-side with 409 for completed rows); (2) no provenance on admin edits.

## Acceptance criteria

- [x] Response status model extended to the workflow statuses; completed →
      "submitted by respondent" semantics preserved for existing rows
      (enum DRAFT/SUBMITTED/EDITED/APPROVED in prisma/schema.prisma;
      migration 20260815160000_response_status_workflow renames COMPLETED →
      SUBMITTED in place via ALTER TYPE RENAME VALUE — verified on a scratch
      DB with a real COMPLETED row converting to SUBMITTED, and on the dev DB
      where seeded COMPLETED rows now show SUBMITTED)
- [x] Status changes persist to the DB with actor (admin/operator user or
      respondent) and timestamp — an audit/history record per response
      (new ResponseAudit model; respondent SUBMIT recorded in
      src/services/response.service.ts; ADMIN_EDIT/APPROVE in
      src/services/response-admin.service.ts with actor userId/name/role from
      the session; detail page renders the history timeline)
- [x] Admin/operator can edit a submitted response; edit records the actor and
      moves status to "edited by admin/operator"
      (editResponseAsAdmin in response-admin.service.ts; wired through
      updateResponseAction in src/lib/actions/responses.ts; browser-verified:
      SUBMITTED → EDITED with audit "Edited by admin/operator by System Admin";
      original completedAt preserved)
- [x] Admin/operator can approve a response; approval is recorded
      (approveResponse service + approveResponseAction + Approve item in the
      responses actions menu; browser-verified: SUBMITTED → APPROVED with audit
      "Approved by admin/operator by System Admin"; APPROVED rows no longer
      offer Approve; server rejects DRAFT approval + double approval +
      editing APPROVED)
- [x] Permissions: same gates as TKT-017 (MANAGE_QUESTIONNAIRES + ownership)
      (updateResponseAction / approveResponseAction both call
      requirePermission(session, "MANAGE_QUESTIONNAIRES") +
      assertCanManageQuestionnaire — identical to TKT-017's actions)
- [x] Public respondent flow unchanged: respondents submit drafts/completions;
      only admins/operators move the workflow statuses
      (FormRenderer sends DRAFT/SUBMITTED; saveResponse rejects any non-DRAFT
      respondent edit with RESPONSE_LOCKED; public API schema accepts only
      DRAFT/SUBMITTED)
- [x] Migration path for existing COMPLETED responses
      (ALTER TYPE "ResponseStatus" RENAME VALUE 'COMPLETED' TO 'SUBMITTED' —
      existing rows convert in place; verified on scratch + dev DBs)
- [x] Unit + integration tests green (workflow transitions, audit records,
      permission gates)
      (318 tests pass on form_gen_test_tkt024: new workflow/audit suite in
      tests/integration/response-admin.service.test.ts — submit audit, admin
      edit actor + EDITED, completedAt preservation, draft edit, approve from
      SUBMITTED/EDITED, reject DRAFT approve, double-approve, edit-approved
      lock, OPERATOR actor; stats test for EDITED/APPROVED completion; all
      existing suites updated COMPLETED → SUBMITTED)
