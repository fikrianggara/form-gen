## Description

Invitation tokens (TKT-001) never expire, are never single-use, and cannot be
revoked. The invitation email claims "This link is personal to you and can be
used once" — but `markInvitationClicked` only stamps `clickedAt`, and nothing
rejects a second click. For `acceptMultipleResponses=true` questionnaires one
leaked/forwarded token yields unlimited responses. From finding F-003.

## Acceptance criteria

- [x] Invitation tokens expire after a configured duration (default 30 days via
      `INVITATION_TTL_DAYS`, measured from `createdAt`); expired tokens are
      rejected with 410 `INVITATION_EXPIRED` and the form shows
      "This invitation link has expired."
- [x] Single-use enforcement: once a response is linked to an invitation, a
      second POST that would mint a new response is rejected with 409
      `INVITATION_ALREADY_USED`; tokens whose linked response is COMPLETED no
      longer open the form (same code). Draft-linked tokens still open the form
      for resume-editing (PATCH-only, no new rows).
- [x] Admin/operator can revoke an invitation via `revokeInvitationAction` +
      Revoke button on each link row in the questionnaire editor's
      "Sample emails & unique links" card; revoked links show a Revoked badge
      and the token is rejected with 403 `INVITATION_REVOKED`.
- [x] Existing invitations keep working during rollout: no data migration
      touches existing rows; expiry is computed from the existing `createdAt`
      (+ TTL), so no token is mass-invalidated on deploy.
- [x] Tests cover expiry, reuse (create + form-open), revoke, and the happy
      path — 8 new integration tests in `tests/integration/invitation.service.test.ts`
      (17 total in file, all green).
