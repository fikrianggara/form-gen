## Description

On the proposal form a user can propose a **new organization** (name +
description) instead of picking an existing one. Today `Proposal.organizationId`
is a required FK (`prisma/schema.prisma:134`) and `approveProposal`
(`src/services/proposal.service.ts:161`) creates only a Survey. When the
proposed org does not exist in the DB and an admin approves the survey, ONE
approval action creates: the organization (from the user's input), the
survey under it, AND an AI-generated questionnaire (via the RAG pipeline)
connected to the survey — 1 action → 1 survey + 1 questionnaire + 1 org
(optional).

Owner request (2026-08-21): "di halaman tambah proposal survei, user bisa
mengajukan organisasi baru. … ketika organisasi ngga ada di db saat tambah
proposal, dan admin approve survei, maka akan kebuat organisasi sesuai
namanya dengan yang diinput user beserta surveinya, dan kebuat kuesioner
berdasarkan AI. jadi 1 aksi pembuatan survei itu akan menghasilkan 1 survei,
1 kuesioner (AI generated), dan organisasi (opsional)."
Owner decision (2026-08-21, analysis v08 Q5): if AI questionnaire generation
fails during approval, **keep the org+survey already created** and **save the
questionnaire description** so the proposer can **retry generation
themselves** later — approval is not rolled back.

## Acceptance criteria

- [ ] Schema: Proposal gains `proposedOrgName String?` + `proposedOrgDescription
      String?` (migration); `organizationId` stays required for existing
      flows but the form offers "New organization…" which fills the proposed
      fields and sets organizationId to null via a new nullable variant OR a
      sentinel — pick one, document it.
- [ ] Proposal form (`ProposalForm.tsx`) has an org selector with a
      "New organization" option (name + description inputs).
- [ ] `approveProposal` happy path, atomic within its own transaction:
      create org (if proposed + missing) → create survey under it → generate
      questionnaire from the proposal (title/purpose/outline via
      `rag.service:generateQuestionnaireFromPrompt`) → connect
      questionnaire↔survey (SurveyQuestionnaire) → mark proposal APPROVED
      with surveyId.
- [ ] Failure semantics (owner decision Q5): if AI generation fails, the org
      + survey REMAIN created and the proposal is marked APPROVED with
      surveyId; the generation intent (questionnaire description built from
      title/purpose/outline) is persisted (e.g. `Proposal.pendingQuestionnaire
      Json?` or a status field) so the questionnaire is NOT silently missing.
- [ ] The proposer (or admin) sees a "Generate questionnaire" action on the
      approved proposal/survey with the saved description pre-filled;
      retrying generation succeeds and connects the questionnaire to the
      survey. Retry is available until the questionnaire exists.
- [ ] **Credit cost (TKT-069, owner decision Q1):** the generation charges
      the **proposer's** credits (5) via `credit.service`; if the proposer
      has insufficient credits at approval time, the org+survey are still
      created and the questionnaire stays pending — the proposer (or a
      topped-up proposer) retries once credits exist; the admin's own
      credits are never spent by approval.
- [ ] Slug collision handling: on approve, if an org with the slugified name
      already exists, link to it instead of creating a duplicate (reuse
      `createOrganization` slug check).
- [ ] The generated questionnaire is DRAFT, titled from the proposal, and
      appears on the questionnaires page with the new survey tag.
- [ ] Existing proposals (with an existing org) approve exactly as before.
- [ ] Integration test: happy path creates org+survey+questionnaire and
      links all three; failed-generation path keeps org+survey and retry
      completes the questionnaire; existing-org path creates no duplicate.

## Notes

- Big and atomic by owner design ("1 aksi… akan menghasilkan"). Keep the
  whole flow in one ticket so the transaction semantics stay coherent.
- Proposal outline rows already capture {title, type} — feed those into the
  AI prompt so the generated questionnaire matches the proposer's intent.
