  request/approval path and promotion, not re-adding the permission.

## 6. Risks

- **R1 — TKT-058 vs TKT-060 layout churn**: both rewrite layouts/nav. If they
  run in parallel branches, merge conflicts are near-certain. Sequence or
  merge nav-shell first.
- **R2 — org role duality**: org-scoped roles (org-operator/org-dev) vs the
  global `Role` enum must stay distinct (Q3/Q4). Conflating them would leak
  system permissions through org management.
- **R3 — TKT-061 atomicity**: an AI failure mid-approval could leave a
  half-created org+survey. Must be transactional or explicitly retryable
  (Q5).
- **R4 — key secrecy**: TKT-066's secret-reveal copy must not persist the
  plaintext in DOM state after dismissal.
- **R5 — registration spam**: signup endpoint needs rate limiting (reuse
  `rate-limit.service`).
