## 3. Design decisions

- **Daily reset is inherent, no cron**: usage is date-keyed
  (`AiCreditUsage(userId, date, used)`); balance(today) = allowance − used +
  Σ dated adjustments. "Reset" = the date key flips; no scheduler needed.
- **Allowance**: `AiCreditConfig.dailyDefault` (single row, default 20) with
  per-user override `User.aiCreditsPerDay` (Q2).
- **"Set kredit user" (Q2)**: BOTH — per-user allowance override AND a dated
  balance adjustment (`AiCreditAdjustment` rows: delta, reason, createdBy) —
  top-up/revoke for the current day with audit.
- **Atomicity**: deduct BEFORE the LLM call inside a transaction (conditional
  `used + cost <= allowance` update — race-safe), refund on LLM failure.
  A failed generation never costs credits; a successful one always deducts.
- **Order of gates**: permission → credits → LLM call.

## 5. Risks

- **R1 — Race conditions**: two concurrent generations on 19 credits must not
  both succeed → transactional conditional update, not check-then-write.
- **R2 — LLM failure billing**: deduct-then-fail without refund charges users
  for nothing → mandatory refund on catch, tested.
- **R3 — TKT-061 credit deadlock**: proposer with 0 credits at approval time
  would block the whole proposal → org+survey still created, questionnaire
  pending until the proposer has credits (Q5-retry semantics from v08).
- **R4 — Add/edit double charge**: TKT-062 must deduct on CONFIRM (after
  preview), not on preview — a discarded AI proposal must cost nothing.
